# Marmite Harness

The marmite package itself — a CLI that drives autonomous agents (orchestrator → builder → verifier) inside a *user's* project. There is no application code in this repo; marmite drives code generation in someone else's working directory.

## Hard Rules

- **The user's app path comes from their `marmite.json`** (`app` field). Never hardcode an app path in prompts, skills, or docs — read the configured value.
- **Do not modify harness internals** (`src/`, `index.ts`) without an explicit ask. The agent protocol, schemas, and state shape are breaking changes for every downstream user.
- **Refactoring is driven by the PRD, not by the harness.** There is no sensor or janitor primitive. The `marmite to-prd` converter injects a "Refactor and harden" story at the end of each epic, and the quality checks that keep debt/drift in check (lint, dependency/architecture checks, typecheck, tests) live in those stories' acceptance criteria. The harness treats them like any other story.
- **All runtime artifacts live under `.marmite/`.** The team-shared artifacts (`prd.json`, `progress.json`, `current-task.json`, `prompts/`) are tracked in git so collaborators share the project history. The two per-developer files — `events.jsonl` (run telemetry) and `feedback.md` (transient steering notes) — are NOT tracked. Never write marmite files to the project root, and never gitignore the tracked artifacts.
- **`prd.json` is not mutated mid-run beyond `passes`.** The PRD is author-time content; the harness only flips the `passes` flag on a story when the verifier signs off. Cross-iteration state (story completions, discovered patterns) lives in `progress.json`'s `timeline` and `patterns` arrays, not in `prd.json`.
- **The `epic-checkpoint` workflow halts at each epic boundary; resumption is derived from immutable state.** The orchestrator agent (per its prompt) stops when it reaches the end of an epic whose stories all pass but that has no approval yet — it writes a `{ "kind": "epic_checkpoint", "epic": "<slug>" }` halt to `current-task.json` instead of selecting a story, and the harness honors it (emits `run_halt`, exits 0). Approval is an append-only `{ "kind": "approval", "epic": "<slug>" }` entry in `progress.json`'s `timeline`, appended by `marmite cook --approve` (never a mutated flag). "Stop vs resume" is a pure function of (`prd.json` passes) + (timeline approvals) — there is no PR/branch/`gh` involvement.
